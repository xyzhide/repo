# pre-publish-check — 公開前点検

前提: 点検対象のURLと公開先は、ユーザーが指定したものに限る。sitetech.jp 本体を対象にする場合は、必ず事前にユーザーの確認を取る。公開そのものはこのスキルでは行わない。

## 点検項目

### 1. canonical 一致
- 対象ページごとに `<link rel="canonical" href="...">` を取り出す。
- 各 href が、そのページの正しい公開URL（https、末尾スラッシュの有無を含む）と一致することを確認する。
- 不一致があれば、ページ一覧と不一致の内容を表にして報告する。

### 2. サイトマップ
- `sitemap.xml` を読み、`<loc>` を一覧にする。
- 公開すべき全ページが含まれていること、下書き・テスト・非公開ページが含まれていないことを確認する。
- XML として正しく解析できることを確認する（例: `python3 -c "import xml.etree.ElementTree as E,sys; E.parse(sys.argv[1])" sitemap.xml`）。

### 3. www・http 転送
- `http://` の URL が `https://` に 1 回で転送されること。
- www あり・なしのどちらか一方の正規の形に統一され、もう一方が正規の形へ 1 回で転送されること。
- リダイレクトがループしないこと（最大回数内で最終ステータス 200 に到達すること）。
- 確認には `curl -sI -L --max-redirs 5 <URL>` を使い、各ホップの Location を記録する。

### 4. 公開URLの読み戻し（公開後）
- 公開後、対象URLを取得し、HTTP ステータス、本文の主要部分、canonical を確認する。
- 読み戻した結果（URL、ステータス、確認した内容）を記録する。推測で「正しい」と書かない。

### 5. 絶対ルールの確認
- 実績・数字に出典または根拠があるか。
- 価格が確定したものだけか。
- 秘密情報（キー、パスワード、トークン）が含まれていないか（`grep -rInE "(AKIA[0-9A-Z]{16}|BEGIN [A-Z ]*PRIVATE KEY|api[_-]?key\s*[:=])" <対象ディレクトリ>` で確認する）。

## 報告の形

| 項目 | 結果 | 根拠（確認したURL・ファイル・値） |
|---|---|---|

結果が「未確認」の項目は、未確認と明記する。全項目が確認できるまで「公開可能」とは言わない。
